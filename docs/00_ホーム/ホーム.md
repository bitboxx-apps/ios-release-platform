# ホーム

このリポジトリ（アプリのプロダクトコード・リリース基盤・仕様）のドキュメントの入口です。
この `docs/` フォルダーは Obsidian の Vault として開けます（リンクは `[[...]]` で書きます）。

## 読む順番
1. [[全体像]] — リポジトリとシステムの構成、ビルドから配布までの流れ
2. [[ドメイン知識]] — アプリの概念とふるまい
3. [[機能の地図]] — 機能ごとの仕様（OpenSpec）とコードの場所
4. [[運用]] — セットアップ、CI/CD、よく使うコマンド
5. [[事故と教訓]] — 実際に起きた問題と再発防止
6. [[用語集]]

## フォルダー
| フォルダー | 書くこと |
|---|---|
| `00_ホーム` | このページ |
| `10_全体像` | システム構成、環境変数の層、リリースの流れ |
| `20_ドメイン知識` | アプリの概念とふるまい |
| `30_機能の地図` | 機能 → OpenSpec の change / spec → コード |
| `40_運用` | セットアップ・CI/CD・ローカル開発の手順 |
| `50_事故と教訓` | 起きた問題・原因・対処・再発防止 |
| `60_用語集` | 用語 |
| `90_テンプレート` | 新しいノートのひな形（[[テンプレート]]） |
| `openspec` | 仕様の正（Source of Truth）。リポジトリ直下の `openspec` はここへのシンボリックリンク |

## 守ること
- 作業のルールは、リポジトリ直下の `AGENTS.md` が正です。ここには、その背景と知識を書きます。
- 仕様は `openspec/` が正です。ドキュメントと仕様が食い違ったら、仕様に合わせてドキュメントを直します。仕様を書き写さず、リンクします。
- 新しいノートは [[テンプレート]] のひな形から作ります。確認できた事実だけを書き、推測は「推測」と書きます。

## Obsidian で開く
1. Obsidian で「フォルダーを保管庫として開く」から、このリポジトリの `docs/` を選ぶ。
2. 設定 → コアプラグイン →「テンプレート」を有効にする（ひな形のフォルダーは `90_テンプレート` に設定済み）。
