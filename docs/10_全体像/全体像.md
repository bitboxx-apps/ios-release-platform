# 全体像

リポジトリの構成と、コードがビルド・配布されるまでの流れ。ディレクトリの詳しいルールは `AGENTS.md` §1、仕様は [[openspec/specs/repo-layout/spec|repo-layout]]。

## リポジトリの構成
| 場所 | 置くもの | 依存してよい先 |
|---|---|---|
| `apps/<platform>/` | プロダクトコード（iOS は `apps/ios/`。bootstrap が Xcode プロジェクトを生成する） | 自分自身、`packages/` |
| `packages/` | （将来）プラットフォームをまたぐ共有物 | `packages/` 内のみ |
| `services/` | （将来）バックエンド | 自分自身、`packages/` |
| `release/<platform>/` | 署名・ビルド・配布の仕組み（bootstrap / scripts / fastlane / match / policies） | 環境変数のみ |
| `.github/workflows/` | CI/CD（`<platform>-<purpose>.yml`） | `release/<platform>/` のスクリプト、`.env.app`、Secrets |
| `docs/` | このドキュメント（Obsidian の Vault）と仕様の実体 `docs/openspec/` | — |

## 環境変数の 3 層
上の層が下の層を上書きする。読み込みは `release/ios/scripts/ensure_idempotency.sh` の `load_env_layers`。
| ファイル | 中身 | git |
|---|---|---|
| `.env.local` | 開発者ごとの上書き | 入れない |
| `.env.app` | アプリの識別情報（`APP_NAME`、Bundle ID など。秘密情報は入れない） | 入れる |
| `.env.platform` | 組織の秘密情報 | 入れない |

## ビルドから配布まで
1. `release/ios/bootstrap/bootstrap.sh --init`（人間が 1 回だけ）: `.env` を作り、Xcode プロジェクト・fastlane の設定・証明書・GitHub Secrets を用意する。
2. push / PR: `ios-ci.yml` が署名なしでビルドとテストをする（`.env.app` が無い間は skip）。
3. タグ `v*` / `ios/v*`: `ios-deploy.yml` が署名ビルドをして TestFlight に送る。

詳しい手順は [[getting-started]] と [[ci-cd]]。
